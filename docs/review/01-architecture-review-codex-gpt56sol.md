1. **Outbound dialing has no exactly-once boundary — High.** **Breaking scenario:** ElevenLabs accepts a call, but the Vercel request times out before `conversation_id`/`callSid` are committed; the watchdog requeues it and dials the pharmacy twice. The documented API has no idempotency field, and even a successful response permits null identifiers. [ElevenLabs outbound-call API](https://elevenlabs.io/docs/api-reference/twilio/outbound-call) **Fix:** atomically create a `dial_attempt` in `starting`, reserve the normalized number for an hour, and pass its UUID as a dynamic variable. Never automatically retry an ambiguous POST; retain the reservation and reconcile it from webhook/provider data.

2. **The “one atomic claim” does not serialize caps or phone locks — High.** **Breaking scenario:** two dispatch functions both observe seven global calls, two calls for one search, and no recent `dial_log`; each claims a different row, producing nine global calls, four for one search, or two calls to the same E.164 number. `UPDATE … WHERE` and row locks do not protect aggregate predicates under normal MVCC. **Fix:** put claiming in one Postgres function guarded by a global transaction advisory lock, re-count inside it, and atomically update a unique `phone_locks(number, locked_until)` row before returning claimed attempts.

3. **The state machine cannot be driven by ElevenLabs’ actual events — High.** **Breaking scenario:** there is no “answered” webhook, so `dialing → talking` never occurs; the final transcription arrives while the row is still `dialing`, and `UPDATE … WHERE status='talking'` becomes a no-op. Voicemail is considered an initiated call and therefore produces transcription rather than `call_initiation_failure`; `wrong_location` is also known only after transcript analysis. [ElevenLabs webhook event semantics](https://elevenlabs.io/docs/eleven-agents/workflows/post-call-webhooks) **Fix:** use observable states such as `queued → starting → awaiting_outcome → transcript_ready → verdict|wrong_location|unreached`; represent answered time separately and allow each final provider event directly from `awaiting_outcome`.

4. **Webhook acknowledgement and background processing are not durable — High.** **Breaking scenario:** ordinary code scheduled after returning 200 may never run on Vercel unless `after()`/`waitUntil()` is used; waiting for dispatch or Claude before responding instead risks failures and webhook disablement. ElevenLabs retries are disabled by default and currently apply only to transcription—not initiation failures. [ElevenLabs retries](https://elevenlabs.io/docs/eleven-api/resources/webhooks), [Vercel post-response work](https://vercel.com/docs/functions/functions-api-reference/vercel-functions-package) **Fix:** verify, deduplicate, and persist a `pending` event in one short transaction, then return 200. Use `after()` only as a fast path; drain a Postgres outbox with Supabase Cron and explicitly enable transcription retries.

5. **Concurrent searches cannot share an in-flight check — High.** **Breaking scenario:** two users request the same pharmacy and medication seconds apart. Both miss the result cache; the first gets the phone lock, but its eventual verdict is never copied to the second because reuse occurs only during `create_search`. The second row waits until the one-hour lock expires and instead times out. **Fix:** model one canonical active check per `(pharmacy_id, medication_id)` and link search targets to it, or add `source_call_id/waiting_shared`; every create/dispatch pass attaches to active work or a fresh verdict, and terminal transitions fan out the result.

6. **Completing a search leaves zombie calls behind — High.** **Breaking scenario:** at 20 minutes `settle_search` marks only the search complete. Its queued retries can subsequently dial because the claim predicate does not require an active, unexpired search, while stale `dialing` rows can continue consuming global slots forever. **Fix:** timeout in one transaction: terminalize all unstarted rows as `cancelled_timeout`, forbid claims where `search.deadline_at <= now()`, and give started attempts a provider deadline plus terminal `outcome_unknown` state. Late webhooks may record evidence but must not reopen or redispatch the search.

7. **The watchdog detects lost webhooks but cannot safely resolve them — High.** **Breaking scenario:** a call completed but its webhook was lost. Marking it unreached and retrying can double-call the pharmacy; leaving it `dialing` leaks a slot. This is especially likely for initiation failures because that event type is not retried. **Fix:** store `provider_deadline_at`; stale rows with a `conversation_id` query ElevenLabs and ingest completed data or extend an in-progress lease. The API exposes conversation status for reconciliation. [ElevenLabs conversation API](https://elevenlabs.io/docs/api-reference/conversations/get/) Attempts lacking provider IDs become `outcome_unknown` without an automatic retry and retain the one-hour phone lock.

8. **Transcript extraction has no durable failure path — High.** **Breaking scenario:** Claude returns 429, times out, or violates the JSON schema once; the row remains `transcript_ready`, the successful pharmacy call never appears, and the search either hangs or completes missing a result. **Fix:** add extraction job fields (`attempts`, `next_attempt_at`, `lease_until`, `last_error`) and claim them from Postgres with bounded retries. After three failures, enter terminal `extraction_failed`/bucket 4 with honest “could not interpret” text; never translate it into a stock verdict.

9. **Anonymous Realtime can expose every search and raw transcript — High.** **Breaking scenario:** subscribing with the project’s public anon key and a client-side search filter is not authorization; another visitor can subscribe broadly and receive postcodes, pharmacy activity, verdicts, or staff speech from the `calls` table. **Fix:** use Supabase anonymous sign-in to obtain a distinct `auth.uid()`, store `owner_id`, and enforce RLS on every browser-readable relation. Supabase explicitly distinguishes anonymous sign-in from the shared anon role. [Supabase anonymous auth](https://supabase.com/docs/guides/auth/auth-anonymous) Publish only a result projection; deny clients all access to calls, events, and transcripts.

10. **There is no server-side admission, spend, or harassment control — High.** **Breaking scenario:** a bot, refresh, or double-click creates many searches, saturates all eight lines, spends the demo budget, and repeatedly targets pharmacies. `check_capacity` is explicitly read-only and therefore provides no protection. **Fix:** require a unique client request UUID, allow one active search per anonymous identity/IP hash, enforce a Postgres token bucket and daily call/minute budget, and add an admin `real_dialing_enabled` kill switch. Only server-side commands may insert searches or calls.

11. **DEV_TEST versus REAL is evaluated too late — High.** **Breaking scenario:** queued DEV rows remain when the deployment flips to REAL; because `resolveDialNumber()` runs at dispatch, old test work starts calling pharmacies. The reverse flip can route many pharmacy rows to one team number while `dial_log` still reasons about intended numbers. **Fix:** snapshot `dial_mode`, intended number, resolved number, agent version, and environment onto each attempt before it becomes claimable. Cancel all nonterminal work during a mode change, and require both REAL mode and a verified pharmacy in the claim function.

12. **Webhook deduplication and transition precedence are unspecified — Medium.** **Breaking scenario:** an identical transcription retry is appended again and triggers duplicate Claude calls or competing verdict writes; a delayed failure event may also overwrite a later final outcome if handlers are loosened to solve the state mismatch. HMAC alone does not prevent replay. **Fix:** validate the signature against the raw request body, enforce timestamp freshness, and insert with a unique key such as `(type, conversation_id, event_timestamp, payload_hash)`. Only newly inserted events may cause effects, and a DB transition function must reject lower-precedence outcomes. [ElevenLabs HMAC and deduplication guidance](https://elevenlabs.io/docs/eleven-agents/workflows/post-call-webhooks)

13. **JSONB does not enforce the PRD’s result invariants — Medium.** **Breaking scenario:** extraction writes `stock=yes` with `location_confirmed=false`, an unreachable row retains a prior stock payload, or bucket 4 receives stock text and the UI renders a forbidden verdict. Nothing described constrains retries to one or provider identifiers to one call. **Fix:** add checks/unique constraints for provider IDs, exact `medication_id`, `(search_id, pharmacy_id)`, and `retry_count <= 1`; require transcript, branch confirmation, and `confirmed_at` for buckets 1–3; compute rank server-side and require terminal failure states to have no stock fields.

14. **Queue and capacity claims cannot satisfy the PRD — Medium.** **Breaking scenario:** a dense radius contains 30 open pharmacies, but only the nearest 12 are silently queued despite “call every open pharmacy.” Twelve average calls already consume four waves; only three average-duration retries fit before 20 minutes, and the stated 22 searches/hour assumes no retries or orchestration overhead. **Fix:** never silently truncate: pre-count candidates and require a narrower radius when the bounded schedule cannot finish. Make retries deadline-aware and present throughput as best-case; drive admission from a small worst-case scheduler rather than queue depth ÷ average drain rate.

15. **Weekly opening sessions cannot enforce “never call closed” — Medium.** **Breaking scenario:** bank-holiday hours, one-off closures, or a session interpreted in UTC marks a pharmacy open when it is closed, producing a paid voicemail call and violating a hard etiquette rule. **Fix:** add date-specific opening overrides and `hours_verified_at`, evaluate all times in `Europe/London`, and refuse calls near a boundary or when demo-day hours are unknown; preload judging-day overrides for the demo area.

**Overall verdict:** Postgres-as-truth is the right core, but the current command/event boundaries are not implementation-safe.  
**Blocking before build:** serialize claiming, redesign the provider-observable state machine, and make webhook/extraction work durable.  
**48h recommendation:** fix findings 1–11 before UI polish; otherwise one timeout, duplicate invocation, or overlapping search can strand the demo or double-call a pharmacy.
